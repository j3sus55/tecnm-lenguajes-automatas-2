# Entregas y límites de la evidencia
El código implementa los cuatro hitos. Un resultado técnico no acredita las
demos ni participación individual. Revisar las cuatro bitácoras y el guion.

Tags requeridos por el curso, sobre commits revisados por el equipo:
```bash
git tag v0.1-hito1 COMMIT_REVISADO_HITO1
git tag v0.2-hito2 COMMIT_REVISADO_HITO2
git tag v0.3-hito3 COMMIT_REVISADO_HITO3
git tag v1.0-hito4 COMMIT_REVISADO_HITO4
git push origin v0.1-hito1 v0.2-hito2 v0.3-hito3 v1.0-hito4
```
Los nombres COMMIT_REVISADO son marcadores que deben sustituirse por SHAs reales.
No se inventan cuatro avances históricos a partir de una implementación única.
La PR de implementación permite revisar el resultado antes de incorporarlo a main.
